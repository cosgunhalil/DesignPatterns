## Project Overview

A Unity project (Unity **6000.3.11f1** / Unity 6) that demonstrates classic game programming design patterns, one self-contained sample per pattern. There is no build pipeline, test suite, or CI — everything is run interactively through the Unity Editor by opening a pattern's scene and pressing Play.

- Open the project in Unity Hub with editor version 6000.3.11f1.
- C# code compiles into the default `Assembly-CSharp` assembly (no asmdefs); the solution file `design-patterns.sln` is generated by Unity for IDE use — don't edit it by hand.
- `Library/`, `Temp/`, `Logs/`, `UserSettings/` are Unity-generated; never modify or search them for project code.

## Architecture

### New template (use this for all pattern work)

Rewritten patterns live under `Assets/Patterns/<Name>/`. **Command is the reference implementation** — mirror it when rewriting the next pattern:

```
Assets/Patterns/<Name>/
├── README.md    — pattern guide: intent, structure, how to run, pitfalls
├── Core/        — the reusable pattern. Pure C# where possible, asmdef
│                  DesignPatterns.<Name> (noEngineReferences: true if engine-free)
├── Sample/      — playable demo. asmdef DesignPatterns.<Name>.Sample referencing
│                  Core; a *Demo.cs MonoBehaviour entry point; Scenes/ subfolder
└── Tests/       — EditMode NUnit tests for Core. asmdef DesignPatterns.<Name>.Tests
                   (Editor-only, UNITY_INCLUDE_TESTS, references Core + TestRunner)
```

Namespaces follow the asmdef names (`DesignPatterns.<Name>`, `.Sample`, `.Tests`). Samples never reference each other. Prefer plain C# classes for pattern participants; MonoBehaviours only where Unity lifecycle/scene presence is needed.

### Rewrite status

All nine legacy pattern samples have been rewritten under `Assets/Patterns/`: Command, Adapter, Builder, Observer, Factory, ObjectPool, Decorator, Component, MVC, State. No legacy `*DesignPattern/` folders remain.

Leftover non-pattern legacy: `Assets/CommonScripts` (`CameraManager` — orphaned after the ObjectPool rewrite; safe to remove in a later cleanup) and `Assets/Resources`.

## Project direction

The repo is being rewritten from scratch into a professional learning resource for junior/mid developers. Goals:

- Clean, advanced, idiomatic C# implementations of each pattern.
- **Separate the pattern from its sample**: the reusable/abstract pattern core lives apart from the game-flavored demo that exercises it (the State pattern's `FiniteStateMachine` core + `PlatformerSample` split is the model to follow).
- Pedagogical quality matters: consistent structure and naming across patterns, and explanatory documentation per pattern.

## Commit style

Follow [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/) strictly: `<type>(<scope>): <description>` — types like `feat`, `fix`, `refactor`, `docs`, `chore`; scope is the pattern or area (e.g. `feat(builder): ...`, `refactor(state): ...`, `docs(readme): ...`). One commit per completed task; keep messages short and clean.

**Never run `git commit`**: propose the commit message for each completed task and let the user commit manually.
